# 威胁模型与缓解

> 对应作业 R4；与 [RWA-技术设计.md](./RWA-技术设计.md) §8、[phase-06-security/log.md](../project-log/phase-06-security/log.md) 对齐。  
> 固定 5 条威胁。每条写「怎么发生」与「代码里怎么防」。

---

## 边界与会计前提

| 点 | 约定 |
|----|------|
| Solidity | **0.8.x 算术溢出默认回滚**（本仓库 `^0.8.24`），不再依赖未检查加减乘 |
| 发息 | `distributeYield` 在 `totalSupply == 0` 时 `revert NoShares`，**不能发息** |
| 净值 | `setNAV(newNav)` 要求 **`newNav > 0`**，否则 `revert ZeroNav`；另有 ±20% 相对变动与抬价偿付护栏 |
| 预言机 | **不接 Chainlink、无外部预言机**；净值为持有 `NAV_MANAGER_ROLE` 者链上 `setNAV` |

## 威胁表（固定 5 条）

| # | 威胁 | 怎么发生 | 代码里怎么防 |
|---|------|----------|--------------|
| 1 | **重入** | 攻击者在 `redeem` / `claimYield` 收到 USDC 的回调（或恶意 ERC20 hook）里再次进入同一函数，企图在状态更新前重复提款。 | Vault 对 `deposit` / `redeem` / `distributeYield` / `claimYield` 使用 OpenZeppelin **`ReentrancyGuard`（`nonReentrant`）**；`redeem` / `claimYield` 遵循 **CEI**：先改份额/`claimable` 再 `safeTransfer`。 |
| 2 | **访问控制**（含非 NAV 角色不能 `setNAV`） | 任意地址调用 `mint` / `burn`、改白名单、`pause`、`distributeYield`、或 **`setNAV` 改价**，伪造份额或操纵兑换价。 | `RWAShare`：`mint`/`burn` 需 `MINTER_ROLE`/`BURNER_ROLE`（仅授予 Vault）；白名单增删需 `DEFAULT_ADMIN_ROLE`。`RWAVault`：**`setNAV` 仅 `NAV_MANAGER_ROLE`**；`distributeYield` / `pause` / `unpause` / `setDepositsOpen` 为 **`DEFAULT_ADMIN_ROLE`**（与改净值分钥）。Admin 可 `grantRole(NAV_MANAGER_ROLE, …)`。Hardhat：非 NAV 角色 `setNAV` 失败；非 Admin `pause` / `distributeYield` 失败。 |
| 3 | **授权** | 用户未 `approve` 或额度不足时仍调用 `deposit`；或合约忽略 `transferFrom` 返回值导致「没扣币却铸份额」。 | 申购路径用 **`SafeERC20.safeTransferFrom`**；失败整笔 revert。单元测试：**未 approve 时 `deposit` 失败**。演示脚本建议精确额度而非无限授权（产品习惯，非链上强制）。 |
| 4 | **暂停与管理员中心化** | Admin 私钥被盗或作恶：长期 `pause` 冻结申购赎回/领息；或滥用白名单。单 Admin 是作业级信任假设。 | 提供 **`pause` / `unpause`（仅 Admin）**，`deposit`/`redeem`/`setNAV`/`distributeYield`/`claimYield` 均 `whenNotPaused`。另：`depositsOpen=false` 只挡新认购，赎回/领息仍可（下架联调）。报告**披露**中心化信任；多签/时效锁列为后续工作。单测：pause 后主路径失败；仅下架时可赎回。 |
| 5 | **净值喂价操纵** | **无 Chainlink**。持有 **`NAV_MANAGER_ROLE`** 密钥者调用 **`setNAV` 抬价/压价**：抬价使同份额赎回更多 USDC（可掏空金库若未注资）；压价使新申购用同样 USDC 拿到更多份额。信任落在 NAV 经理（可由 Admin 授予，与 pause/派息分钥）。 | **产品设计即中心化喂价**，不是误报漏洞。链上约束：`onlyRole(NAV_MANAGER_ROLE)` + `newNav > 0` + **单次相对变动 ≤ ±20%（`NavChangeTooLarge`）** + **抬价时 `USDC.balanceOf(vault) >= totalSupply * newNav / 1e6 + 未领利息`（不足 `InsufficientReserve`，须先注资）** + `whenNotPaused`；`setNAV` **不**改 `rewardIndex`（与派息分轨，禁止改 nav 当发息）。缓解靠：**角色拆分披露**、护栏单测、演示不接外部预言机、不开放二级订单簿。 |

## 与测试 / 静态分析的对应

| 威胁 | Hardhat | Slither | Echidna |
|------|---------|---------|---------|
| 重入 | CEI + guard 已编入合约；ERC20 回调面有限 | 未见对本 Vault 的 High 重入告警 | — |
| 访问控制 / `setNAV` | 非 NAV 角色失败；Admin 可授 NAV_MANAGER | 特权属预期，不作 High 误修 | 准入：非白名单余额 0（移出前须清仓） |
| 授权 | 未 approve 失败 | — | — |
| 暂停 / 中心化 | pause 全路径 + 下架仅挡 deposit + 非 Admin | 见 [Slither 说明](./Slither扫描说明.md) | harness 可 pause/unpause |
| 净值喂价 | 超幅度 / 偿付不足失败、改价后数量变化、`setNAV(0)`、分轨 | 同左文档「产品设计」说明 | 偿付不变量（抬价时 harness 补资；采样在 ±20% 内） |

详细命令与是否跑通见 [phase-06-security/log.md](../project-log/phase-06-security/log.md)。
