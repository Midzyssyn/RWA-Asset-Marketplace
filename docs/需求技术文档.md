## 2. 背景与目标

### 2.1 要解决的问题

多家公司希望把**链下托管资产的收益权**做成可认购份额；合格投资人希望用稳定币完成交割，并按份额领取收益。传统做法里，准入名单、打款、份额账本、净值往往分散在表格与人工流程中，规则可被私下改动，交割容易半成功。

本项目用智能合约把**准入、申购/赎回原子结算、净值换算、派息会计、暂停**固化在链上，前端只作为触发入口。

### 2.2 一句话目标

在以太坊测试环境上，提供一个**多公司 RWA 资产市场**：每家公司一个独立份额金库；投资人浏览市场、完成该项目投资者准入后认购 / 赎回 / 领取收益；项目方可更新净值、分配收益、暂停本项目柜台，互不影响其它项目。

### 2.3 成功标准（产品级）

1. 市场页能列出 **3 个**、分属不同公司的已上架项目（见 §2.5），且每个项目可独立认购 / 赎回。
2. 投资人走完「准入 → Approve → 认购 → 赎回 / 领息」主路径，交易在链上可验证。
3. 对项目 A 改净值或认购，项目 B 的份额余额与金库 USDC **不变**。
4. 未准入地址无法持有或接收份额（链上 revert，而非仅前端藏按钮）。
5. 演示与报告中明确：教学产品，非真实证券。

### 2.4 诚实边界（必须写进需求，不可当作缺陷）

| 声明 | 含义 |
|------|------|
| 教学演示 | 非真实证券发行、非持牌经纪 |
| MockUSDC | 不是真美元；仅 Owner 可 mint |
| 白名单 | 模拟投资者准入，**不是**真实 KYC / 证件核验 |
| `setNAV` | 项目 `NAV_MANAGER_ROLE` 中心化喂价，**不是** Chainlink |
| 下架 ≠ 暂停 | Registry `setListed` 只管目录；Vault `pause` 才锁柜台写操作 |
| 信任假设 | 落在平台 Registry Owner、各项目 Admin / NAV 经理的私钥 |

## 3. 用户角色与权限需求

### 3.1 角色定义

| 角色 ID | 业务名称 | 链上身份 | 目标 |
|---------|----------|----------|------|
| R-PLT | 平台运营 | `ProjectRegistry` Owner | 登记项目、上架 / 下架目录 |
| R-ADM | 项目方管理员 | 该项目 Share/Vault `DEFAULT_ADMIN_ROLE` | 准入、派息、暂停、开关认购、授予 NAV 角色 |
| R-NAV | 净值经理 | 该项目 `NAV_MANAGER_ROLE` | 仅更新净值（受护栏约束） |
| R-INV | 投资人 | 已在该项目 `RWAShare` 白名单的 EOA | 认购、赎回、领收益 |
| R-MNT | 铸/毁执行器 | 仅该项目 `RWAVault` 地址 | `mint` / `burn` 对应 `RWAShare` |

演示建议使用**不同钱包**扮演平台、项目 Admin、NAV 经理、投资人，以体现权限已在合约拆分。同一地址兼任时功能仍可用，但不能把「兼任」说成「角色未拆」。

| Mint MockUSDC（测试币） | ✓（USDC Owner，常与部署者同一） | | | |
| `setDepositsOpen` | | ✓ | | |
| `setNAV` | | 仅当兼任 NAV | ✓ | |
| `distributeYield` | | ✓ | | |
| `pause` / `unpause` | | ✓ | | |
| `deposit` / `redeem` / `claimYield` | | | | ✓（须白名单；认购还须 `depositsOpen` 且未 pause） |
| 自己 mint 份额 | | | | ✗ |

**REQ-AUTH-03** 前端隐藏按钮不等于安全；鉴权必须在合约生效。

## 4. 范围

### 4.1 纳入（In Scope）

- 共用 MockUSDC + 多项目目录 `ProjectRegistry`。
- 每项目独立 `RWAShare` + `RWAVault`（方案 B：脚本部署多套后 `register`，无 Factory）。
- 投资者准入、申购、赎回、暂停、简易 pull 派息。
- 每项目中心化 `setNAV`（含 ±20% 与抬价偿付护栏）。
- 市场 / 项目详情 / Admin 前端；钱包连接；演示角色切换。
- Hardhat 单测、Slither、Echidna；本地 Hardhat（31337）与 Sepolia（11155111）。

### 4.2 明确不做（Out of Scope）

- 真实 KYC、证件存储、链下文件 / IPFS。
- 真美元、主网真实证券、持牌合规体系。
- Chainlink 或其它外部预言机。
- 二级订单簿、跨项目合并金库、项目间份额撮合。
- 代理升级（Transparent / UUPS）、多签、时效锁。
- 完整 ERC-3643。
- 旧路径「资料上架下载」（`legacy/DataCoin.sol` 等）不进入主产品。

### 5.3 许可份额（RWAShare）

| ID | 需求 | 优先级 | 验收 |
|----|------|--------|------|
| FR-SHR-01 | 每项目独立 ERC-20 份额，`decimals = 6` | P0 | 项目间 `totalSupply` 互不影响 |
| FR-SHR-02 | Admin 可单地址 / 批量增减白名单，发 `WhitelistUpdated` | P0 | 批量循环长度由调用方控制 |
| FR-SHR-03 | 用户互转：双方均须白名单，否则 revert | P0 | 转给陌生人失败 |
| FR-SHR-04 | mint 接收方、burn 发送方须在白名单 | P0 | 未准入无法被铸份额 |
| FR-SHR-05 | 仅 `MINTER_ROLE` / `BURNER_ROLE` 可 mint/burn，部署后授予本项目 Vault | P0 | 投资人直接 mint revert |
| FR-SHR-06 | Admin `setVault`；用户互转前回调 Vault `accrue(from/to)`；mint/burn 不回调（由 Vault 先行结息） | P1 | 互转不导致利息错领 |
| FR-SHR-07 | 非白名单地址份额余额恒为 0；`removeFromWhitelist` 在 `balanceOf > 0` 时 revert（须先赎回/清仓） | P0 | 单测（有仓移出失败）+ Echidna 不变量 |

### 5.4 金库柜台（RWAVault）

| ID | 需求 | 优先级 | 验收 |
|----|------|--------|------|
| FR-VLT-01 | `deposit(assets)`：未暂停、`depositsOpen`、调用者白名单、非重入；扣 USDC 并按 nav 铸份额，同一交易原子完成 | P0 | 失败则整笔回滚 |
| FR-VLT-02 | 份额公式：`shares = assets * 1e6 / nav`；结果为 0 则 revert | P0 | `nav=1e6` 时 1:1 |
| FR-VLT-03 | `redeem(shares)`：先结息，再 burn，再按 `assetsOut = shares * nav / 1e6` 退 USDC（CEI） | P0 | 与申购对称 |
| FR-VLT-04 | `depositsOpen=false` 时拒绝新 `deposit`；`redeem` / `claimYield` 在未 pause 时仍允许 | P0 | 下架联调场景 |
| FR-VLT-05 | `pause` 后 `deposit` / `redeem` / `setNAV` / `distributeYield` / `claimYield` 全部失败；其它项目不受影响 | P0 | 隔离验收 |
| FR-VLT-06 | 初始 `nav = 1e6`（1 份额 = 1 MockUSDC） | P0 | 部署后可读 |

### 6.1 资金与会计不变量（测试 / 模糊测试应对齐）

1. **无派息且 nav 恒为 `1e6`：** `USDC.balanceOf(Vault) == Share.totalSupply()`。
2. **无派息、nav 可变：** `USDC.balanceOf(Vault) >= Share.totalSupply() * nav / 1e6`（整数除法允许尘埃，用 `≥`）。
3. **有派息：** 金库余额 ≥ 按 nav 计价的本金索取 + 未领利息会计合计。
4. **准入：** 非白名单 `Share.balanceOf == 0`。
5. **跨项目：** 操作项目 A 不改变项目 B 的上述关系。

## 7. 技术架构需求

### 7.1 总体架构

```text
链下：React DApp（Vite + wagmi + viem）  |  作业报告 / 演示脚本  |  人工模拟 KYC
链上：MockUSDC（共用）
      ProjectRegistry（目录）
      项目 i：RWAShare_i  ←mint/burn→  RWAVault_i
```

**REQ-ARCH-01** 一项目一套金库，禁止做成跨项目巨无霸单池。

**REQ-ARCH-03** 信任关键状态必须在链上：余额、白名单、paused、depositsOpen、nav、rewardIndex、角色。

## 8. 接口规格（实现必须遵守）

### 8.1 净值与金额缩放

- MockUSDC、RWAShare、`nav` 均为 **6 位小数**。
- `nav == 1_000_000` 表示 1 份额兑 1 mUSDC。
- 派息指数精度 `INDEX_PRECISION = 1e18`。

### 8.2 核心换算

```text
deposit:  shares    = assets * 1e6 / nav
redeem:   assetsOut = shares * nav / 1e6
yield:    rewardIndex += amount * 1e18 / totalSupply
          owed = balance * (rewardIndex - userIndex) / 1e18
```

### 8.3 关键事件

| 合约 | 事件 |
|------|------|
| ProjectRegistry | `ProjectRegistered`、`ProjectListedUpdated` |
| RWAShare | `WhitelistUpdated`、`VaultUpdated` |
| RWAVault | `Deposited`、`Redeemed`、`NavUpdated`、`YieldDistributed`、`YieldClaimed`、`DepositsOpenUpdated` |

## 9. 主用户故事与验收场景

### 9.1 投资人认购

1. 打开市场，看到 ≥2 个不同公司项目。
2. 进入 `/project/:id`，Admin 已对该地址准入并 mint 了 mUSDC。
3. 输入认购额，UI 按当前 nav 显示预估份额。
4. Approve（如需要）→ deposit；份额增加、mUSDC 减少。
5. 未准入钱包执行同一操作，交易失败。

### 9.2 净值变更

1. NAV 经理将 nav 从 1.0 改为 1.10（≤20%）。
2. 若金库不足以按新价兑付已发行份额 + 未领息，交易失败。
3. 成功后，同样 100 mUSDC 认购得到的份额变少；赎回同份额得到更多 mUSDC。
4. 派息会计不变。

### 9.3 下架 vs 暂停

1. 平台 `setListed(false)`：市场默认不再展示；项目方联调 `setDepositsOpen(false)` 后新认购失败，已持有者仍可赎回 / 领息。
2. 项目方 `pause()`：本项目认购、赎回、改净值、派息、领息全部失败；其它项目正常。

### 9.4 隔离

对项目 A `setNAV` 或 `deposit` 后，项目 B 的 `Share.balanceOf`、`Vault` USDC 余额、`nav` 与项目 A 操作前一致。
