# 运维与升级说明

> 对应作业 R5。本项目为课程教学演示，非生产级 RWA 产品。  
> **下架 ≠ 暂停、setNAV / 角色 / 范围外** 强制规则见 [下架与暂停对照.md](./下架与暂停对照.md)（报告第 2/5 章可直接摘录）。

---

## 1. 升级策略：合约不可升级

本仓库**不使用** Transparent Proxy / UUPS 等代理模式。三份合约（`MockUSDC`、`RWAShare`、`RWAVault`）部署后逻辑固定。

| 选择 | 理由 |
|------|------|
| 不接代理 | 降低代理管理权、实现合约与存储槽等攻击面；适合从 0 的课程周期 |
| 变更方式 | **暂停旧池 → 部署新合约 → 用户到新池重新申购**（教学可接受） |
| 生产对比 | 真实 RWA 通常需要更严肃的迁移、多签与治理；本作业不实现 |

**诚实边界：** 「不可升级」不等于「没有中心化风险」。Admin 密钥仍可暂停业务、改白名单、调用 `setNAV`。

---

## 2. 出问题怎么办：先 pause，再新部署

运行期止损顺序：

1. **项目方 Admin 调用该项目 `RWAVault.pause()`**（不是 Registry `setListed(false)`）  
   冻结资金进出与净值/派息相关写操作：`deposit` / `redeem` / `setNAV` / `distributeYield` / `claimYield` 均 `whenNotPaused`，调用应失败。  
   仅下架只影响市场展示与新认购入口，**不能**当作应急资金锁定。
2. **链下沟通**：通知演示账户停止操作；在 Etherscan 确认 `paused() == true`。
3. **修复与替换**：在仓库修代码 → 本地测通 → **重新部署**一套合约（含 Registry 与各项目 Share+Vault）→ 重新授予 Vault 的 mint/burn 角色 → 更新前端地址与 README。
4. **旧池**：保持暂停；教学场景不做自动迁移资金脚本。

无 24h 值班。日常「监控」= 看 Sepolia Etherscan 最新交易与事件即可。

## 3. 有意的中心化设计（须在报告中披露）

以下能力属特权角色（`DEFAULT_ADMIN_ROLE` / `NAV_MANAGER_ROLE` / Ownable），属于产品设计，不是误报漏洞：

| 能力 | 操作者 | 作用 | 信任假设 |
|------|--------|------|----------|
| `setListed` | 平台 Registry Owner | 目录上架/下架；不锁资金 | Owner 私钥可信 |
| `pause` / `unpause` | 项目 Vault Admin | 应急停掉申购、赎回、改净值、注息、领息 | Admin 私钥可信；被盗则可冻结用户资金进出 |
| `setNAV` | 项目 `NAV_MANAGER_ROLE`（Admin 可授） | 中心化净值喂价；±20% + 抬价偿付护栏 | 净价链上提交；**不是** Chainlink；≠ pause/派息同一把钥匙 |
| 白名单增删 | 项目 Share Admin | 模拟投资者准入 | 名单由项目方维护，链下假设已人工审核 |
| `MockUSDC.mint` / `distributeYield` | USDC Owner / Vault Admin | 发测试币、注入利息 | 仅测试网演示 |

**明确不做：** 真 KYC、真美元、主网证券、二级订单簿、跨项目合并金库、外部预言机（含 Chainlink）、多签 Admin、时效锁。

报告与答辩应直接说清：信任落在持有 NAV / 暂停角色私钥的人；抬高 NAV 前须保证金库 USDC 足以兑付，否则先注资或先演示下调。

## 4. 日常运维清单（作业级）

- 私钥：仅测试网专用账户；从不提交 `.env`。
- 地址与验证链接：以 README 表格为准；重新部署后同步更新。
- 演示前：确认未 pause、`nav` 符合剧本、投资者已白名单且有余额。
- 演示上调 NAV 前：检查 `USDC.balanceOf(Vault)` 是否够按新净值兑付已发行份额。
